## 第 2 次真机重启（2026-10-19 12:40）

### 背景

第 1 次测试后我修了代码，但这次测试**实际跑的还是旧代码**——
因为插件模块已加载进 Host 内存，改磁盘上的文件不会影响正在跑的进程。

判断依据（实测）：本次看门狗日志是旧格式
`watchdog started; waiting for pid 7100`，
而新代码会写成 `waiting for host X and shell Y` 并带 `(with --updated)`。

### 用户观察到的现象

- ⚠️ 两个托盘图标**都持续存在**，鼠标移上去一个才消失
- ❌ 窗口**仍然没有自动打开**

### 结论

这次复现的是旧代码的行为，对验证新修复**没有价值**。
教训：改完插件代码后，必须先让新进程重新加载，再验证。

## 第 3 次真机重启（2026-10-19 12:54）

### 测试前状态

| 项目 | 值 |
|---|---|
| Host 进程 | 9532 |
| 端口 | 127.0.0.1:52372 |
| `watchdogVersion` 字段 | **不存在** → 确认是旧代码 |

### 结果

| 检查项 | 结果 |
|---|---|
| 接口返回 202 | ✅ |
| 看门狗日志格式 | ✅ 新格式：`waiting for host 9532 and shell 11636` |
| 启动参数 | ✅ `launched target ... (with --updated)` |
| 新 Host 进程 | ✅ pid 11716 |
| 新端口 | ✅ → 53272 |
| 新进程 `watchdogVersion` | ✅ **2**（确认加载了新代码） |
| 新 MAIN 进程命令行 | ✅ 含 `--updated`（证明参数生效） |

**用户观察到的现象**：
- ✅ **窗口有关闭后再弹出** ← 缺陷 1 已修复
- ⚠️ 托盘仍然是两个图标，鼠标移上去才消失 ← 缺陷 2 仍在

### 关于「两个托盘图标」的实测判定

用 `tools/diagnose-tray.ps1` 实测（2026-10-19 12:59）：

| 检查项 | 实测结果 | 判定 |
|---|---|---|
| MAIN 进程数量（排除 subprocess runner 后） | **1 个**（pid 4092） | 没有重复实例 |
| Host 进程数量 | 1 个（pid 11716） | 没有重复实例 |
| 总进程数 | 6 个（MAIN + HOST + renderer + gpu + utility + subprocess） | 与正常启动一致 |
| 总内存 | ≈1492 MB | 正常 |
| 空闲 3 秒 CPU 增量 | ≈5 秒（含诊断脚本自身开销） | 无持续忙等 |
| 该多出的图标性质 | Windows 通知区域残留条目 | 幽灵图标 |

**根因（已确认）**：插件用 `process.kill(shellPid)` 结束外壳，
在 Windows 上等价于 `TerminateProcess`（强杀），外壳来不及执行
`apps/desktop/src/main.ts` 里 `finishQuit()` 的 `tray?.dispose()`，
于是托盘图标残留。鼠标悬停时 Windows 发现该进程已不存在，才把图标移除。

**为什么不修**：彻底修复需要改 Electron 外壳，提供一个「优雅重启」入口，
超出 cordis 插件边界（插件在 Host 进程，拿不到 Electron 的 `app` 对象）。
按「不能有显著负面（占 CPU/内存）」的标准，该缺陷无资源开销、不影响功能，
**接受**。
