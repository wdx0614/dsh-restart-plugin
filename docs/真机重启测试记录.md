# 真机重启测试记录

## 测试目的

证明「在界面点重启 → 应用真的关闭 → 应用真的自动重新打开」这条链路在真实
DSH 桌面版上成立。这是单元测试与进程级仿真都替代不了的一步。

## 测试前状态（实测，2026-10-19 12:17）

| 项目 | 值 |
|---|---|
| 应用主进程（Electron） | 11756 |
| Host 进程 | 12168（父进程 11756） |
| 本地端口 | 127.0.0.1:59307 |
| 插件安装状态 | 已安装，`application: applied` |
| Host 路由 `GET /dsh-restart-plugin/api/status` | HTTP 200，`supported: true` |
| Client slot `sidebar.footer.action` | `dsh-restart-plugin` 已注册，`active: true` |

## 测试方式

通过插件自己的 REST 接口触发（等价于界面点确认按钮）：

```
POST http://127.0.0.1:59307/dsh-restart-plugin/api/restart
Content-Type: application/json
{"force": true}
```

`force: true` 是因为测试当时本会话自身算「有活动任务」，需要显式跳过任务确认。

## 预期

1. 接口先返回 202（让界面能显示"正在重启"）；
2. 约 0.25 秒后 Electron 主进程 11756 被结束；
3. Host 12168 因 IPC 断开而优雅退出；
4. 看门狗发现 12168 消失后，重新启动 `DeepSeek Harness.exe`；
5. 新进程有新的 pid，端口重新分配，界面恢复可用。
