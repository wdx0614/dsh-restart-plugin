# 实现原理与风险说明

> 本文件用大白话讲清楚"它是怎么做到的"和"哪里可能出问题"。
> 每一条结论都标了可信度，**没有验证过的会明确写出来**。

---

## 一、为什么"重启"这么难

普通程序想重启很简单，调用一个"重新启动自己"的函数就行。
但 DSH 桌面版是**两层结构**：

```
DeepSeek Harness.exe   ← Electron 外壳（管窗口、托盘）
        └── Host 进程    ← 真正跑插件、会话、工具的那层
```

插件是运行在 **Host 进程**里的。插件想让整个应用重启，得让上面那个"外壳"重新启动自己，
但**插件碰不到外壳的代码**（外壳是编译进 app.asar 的 Electron 程序，插件机制够不到）。

更麻烦的是：插件自己就活在要关闭的进程里。
"关掉自己之后再把自己打开"这件事，逻辑上不可能由自己完成。

## 二、我的做法：请一个"看门狗"来干这件事

打个比方：你让助理帮你关灯再开灯，但关灯之后助理也看不见了。
所以要先叫一个**站在门外的**人，让他等你把灯关了，再帮你打开。

具体是三步：

### 第 1 步：先叫醒看门狗

点「重启」时，插件会在系统里启动一个**独立的小进程**（就叫它看门狗）。
它和 DSH 完全分开，DSH 关掉它也不会跟着关。

看门狗拿到三个信息：
- 要等哪个进程退出（Host 的 pid）
- 还要等哪个进程退出（外壳的 pid）
- 退出之后要重新启动哪个程序（`DeepSeek Harness.exe`）

### 第 2 步：关闭应用

插件先结束外壳进程，外壳一退，Host 的通信通道断开，Host 就会走它**自带的正常退出流程**
（把会话数据写完、关掉存储、清理子进程），然后自己退出。

这一步是"优雅退出"，不是硬杀，所以不会丢数据。

### 第 3 步：看门狗把应用拉回来

看门狗确认两个进程都消失了，再等一小会儿（让系统回收托盘图标、释放文件锁），
然后用正确的参数重新启动 `DeepSeek Harness.exe`。

重新启动时做了三件关键的事：

| 做法 | 为什么 |
|---|---|
| 去掉 `ELECTRON_RUN_AS_NODE` 环境变量 | 不去掉的话，新启动的会是"Node 模式"，**不会出现窗口**，看起来像没重启成功 |
| `windowsHide: false` | 用 `true` 会让 Windows 以"隐藏"方式启动窗口，结果只留一个托盘图标 |
| 带上 `--updated` 参数 | 这是外壳自己认的"重启"标记，带它启动后窗口会**主动置顶并聚焦** |

## 四、已知缺陷与风险

### 缺陷 1：重启后可能出现两个托盘图标（悬停才消失）

**现象**：重启完成后，任务栏右下角短时间内（或一直）有两个 DSH 托盘图标，
鼠标移上去其中一个就消失了。

**是什么**：Windows 的"幽灵图标"（orphaned tray icon）。
旧的应用实例被结束得太快，系统没来得及把它注册的托盘图标移除。

**危害评估**（已实测）：

| 担心的事 | 实测结果 |
|---|---|
| 是不是多启动了一个实例？ | ❌ 不是。MAIN 进程只有 1 个（诊断工具实测） |
| 会不会额外占内存？ | ❌ 不会。总内存约 1.5 GB，属正常范围 |
| 会不会额外占 CPU？ | ❌ 不会。空闲 3 秒 CPU 增量约 0~5 秒（含诊断本身开销），无持续忙等 |
| 会不会影响功能？ | ❌ 不会，鼠标移过就消失 |

**根治为什么没做**：需要改 Electron 外壳代码，让它提供一个"优雅重启"接口
（类似 `app.relaunch()`），这超出了 cordis 插件的边界——
插件在 Host 进程里，够不到外壳的 Electron API。
**结论：接受这个缺陷，不影响使用。**

### 缺陷 2（⚠️ 未验证）：极少数情况下看门狗可能没能拉起应用

**可能场景**：
- 应用安装路径被改动或文件损坏
- 系统权限阻止启动子进程
- 安全软件拦截

**兜底措施**：看门狗有 60 秒超时；如果超时会强制结束残留进程再启动。
如果真的没能启动，用户手动点图标打开即可——数据不会丢（因为 Host 是优雅退出的）。

### 风险 1：重启会中断正在运行的任务

这是**设计如此**：重启意味着应用关闭，正在跑的对话/工具调用必然被中断。
所以插件在重启前会检查，有活动任务时要求二次确认（按钮变成「仍然重启」）。

### 风险 2：只在桌面版可用

在 `dsh web`（浏览器里开的）或开发环境下，插件会明确返回"不支持重启"，
**不会**假装能重启。这是故意的保守设计，判据是 `process.execPath` 是否以
`DeepSeek Harness.exe` 结尾。

## 五、这个插件改了什么、没改什么

**改了的**：
- 在你的 DSH profile（`~/.dsh/profiles/desktop`）里安装了一个本地插件
- profile 的 `package.json` 多了一条 `"dsh-restart-plugin": "link:<本仓库路径>"` 依赖
- 启动时会在系统临时目录写一个 `dsh-restart-watchdog-*.log` 日志

**没改的**：
- ❌ 没有修改 DSH 安装目录里的任何文件（没有动 `app.asar`）
- ❌ 没有修改系统配置、注册表、计划任务
- ❌ 没有联网、没有收集任何数据
- ❌ 没有改动你的其他插件

**怎么彻底还原**：在插件页面卸载本插件，然后重启应用即可。
profile 的备份在 `.ai_backup/install-asm-bundle/20261019-121114/`（本仓库内）。
